## Plain English Summary

### The Problem

The agent pipeline runs asynchronously — triage classifies, log analyst fetches logs, deploy correlator ranks deploys, remediation drafts a rollback, comms writes a summary. But if you're watching a dashboard or an SSE stream, you have no way to know what's happening *right now*. The pipeline is a black box until it finishes.

The event bus is the bridge between the agent pipeline and any real-time consumer (SSE endpoint, dashboard, WebSocket client). When an agent starts, completes, calls a tool, gets a result, or hits a HITL gate, the pipeline publishes an event. Connected clients receive it instantly.

### What Was Built

**`EventType`** — a `StrEnum` with 7 event types matching the pipeline lifecycle:
- `agent_started` / `agent_completed` — bracketing each specialist's work
- `tool_called` / `tool_result` — individual tool invocations
- `hitl_requested` / `hitl_resolved` — the human approval gate
- `incident_resolved` — terminal event

**`PipelineEvent`** — a Pydantic model carrying `type`, `agent_name`, `timestamp`, `incident_id`, and a flexible `data` dict for event-specific payload. Serializes cleanly to JSON for SSE `data:` lines.

**`EventBus`** — the pub/sub core. Design:
- One `asyncio.Queue` per subscriber per incident (created on `subscribe()`)
- `publish(incident_id, event)` fans out to all queues for that incident, returns subscriber count
- `unsubscribe()` removes a single queue
- `close_incident()` sends a `None` sentinel to every subscriber (so they can break out of their `async for` loop) and cleans up all queues
- `subscriber_count` / `incident_subscriber_count` for introspection

### Key Decisions

**asyncio.Queue per subscriber, not a shared broadcast:** Each connected SSE client gets its own queue. This means a slow consumer doesn't block others — each queue has its own backpressure (`max_size=256`). The alternative (a single queue with multiple readers) would require complex cursor management.

**`None` sentinel for clean shutdown:** When an incident resoletes or the pipeline errors, `close_incident()` pushes `None` into every queue. The SSE endpoint can do `while (event := await q.get()) is not None: yield event` — clean, no exceptions, no polling.

**No persistence:** The event bus is purely in-memory, ephemeral. Events are for real-time streaming, not replay. The trajectory file (from `SentinelTracer`) is the durable record.
