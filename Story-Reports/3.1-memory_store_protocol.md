## Plain English Summary

### What problem this solves

Sentinel has two different kinds of memory — semantic memory (what services exist, what their runbooks say) and episodic memory (past incidents, stored as embeddings for similarity search). For the MVP these are both SQLite, but the ARCHITECTURE.md Phase 2 roadmap replaces them with Cosmos DB. Without a shared interface, swapping the backend would require hunting down every place in the codebase that creates a memory object and updating it. The `MemoryStore` protocol defines the contract that any memory backend must satisfy, so a Cosmos DB implementation can drop in as a replacement for the SQLite one without touching any callers.

### What was built

`MemoryStore` is a Python `Protocol` — a structural interface that a class satisfies by having the right methods, without needing to inherit from anything. It has four async methods:

- **`store(record)`** — persists a record (upsert semantics)
- **`query(query_input, *, top_k=5)`** — searches the store; for episodic memory this is a cosine similarity search over embedding vectors, for semantic memory it's a structured lookup by service name or failure class
- **`get(record_id)`** — retrieves a single record by primary key; returns None if absent
- **`delete(record_id)`** — removes a record; no-op if it doesn't exist

All methods are async because every concrete implementation uses I/O — aiosqlite for the SQLite backend, network calls for a future Cosmos DB backend. Making the protocol async-only prevents accidentally writing a sync implementation that would block the event loop.

The protocol is marked `@runtime_checkable`, which means code can use `isinstance(store, MemoryStore)` to verify an object satisfies the protocol at runtime. This is useful in dependency injection — the FastAPI lifespan handler can verify that whatever object was injected looks like a MemoryStore before the first request arrives.

### Key decisions and trade-offs

**`Any`-typed signatures instead of generics** — A generic `MemoryStore[T]` protocol would give better type safety (e.g. `EpisodicMemory` is `MemoryStore[EpisodicRecord]`). But making `query()` generic is problematic: EpisodicMemory's query input is a `list[float]` embedding vector, while SemanticMemory's is a service name `str` — there's no single type parameter that covers both. Using `Any` explicitly is honest about this: the protocol guarantees the four methods exist and are async; the concrete implementations add their own typed methods (`store_incident`, `search_similar`, `get_service`, `get_runbook`) on top.

**`runtime_checkable` limitation documented in tests** — `runtime_checkable` only checks that the attribute *names* exist — it doesn't verify that the methods are async. A class with sync methods named `store`, `query`, `get`, `delete` passes the `isinstance` check at runtime. The test `test_sync_store_passes_runtime_check` documents this limitation explicitly, with a comment noting that pyright catches async/sync mismatches statically. Runtime checks are a safety net, not a guarantee.

**`top_k=5` default on `query()`** — The ARCHITECTURE.md specifies returning top-5 similar past incidents from episodic memory search. Setting the default on the protocol's `query()` method makes this convention visible at the interface level, and tests verify that any conforming implementation inherits the same default.
