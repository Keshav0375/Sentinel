## Plain English Summary

### The Problem

Before this task, Sentinel's config had a fundamental limitation: the model field defaults
(`sentinel_triage_model`, `sentinel_analysis_model`, `sentinel_judge_model`) were bare
model names like `"llama-3.1-8b-instant"` — they had no provider information baked in.
The system also had no config fields for any API keys besides Groq. This meant there
was no way to configure Sentinel to use Anthropic or OpenAI just by changing environment
variables; you'd have to change code.

There was also no safety net: if someone set `SENTINEL_ANALYSIS_MODEL=anthropic/claude-sonnet-4-6`
but forgot to set `ANTHROPIC_API_KEY`, Sentinel would start up successfully, then crash
mid-incident when the first API call failed. That's the worst time to discover a
misconfiguration.

### What Was Built

**Step 1 — Model string format change.**
The three model fields now default to the `provider/model` format:
- `sentinel_triage_model`: `"groq/llama-3.1-8b-instant"`
- `sentinel_analysis_model`: `"groq/llama-3.3-70b-versatile"`
- `sentinel_judge_model`: `"groq/llama-3.1-8b-instant"`

The provider prefix (`groq/`, `openai/`, `anthropic/`, `azure/`) is what the provider
layer (built in task 9.3) will read to route API calls. The default provider is still
Groq — nothing changes for the dev setup.

**Step 2 — New optional API key fields.**
Five new fields were added to Settings:
- `openai_api_key` — for `openai/` prefixed models
- `anthropic_api_key` — for `anthropic/` prefixed models
- `azure_api_key` — for `azure/` prefixed models
- `azure_api_base` — Azure resource URL (also needed for Azure)
- `azure_api_version` — defaults to `2024-02-01`

All five are optional (empty string default) at the field level. They become required
only when the matching provider prefix appears in a model string — enforced by the
validator in Step 3.

**Step 3 — Cross-field validator.**
A `@model_validator(mode="after")` was added. It runs after all fields are set (including
defaults and env var overrides) and walks the three model fields. For each model string
that starts with a known provider prefix, it checks the matching API key:

- `groq/` → `groq_api_key` (already required; skipped)
- `openai/` → `openai_api_key` must be non-empty
- `anthropic/` → `anthropic_api_key` must be non-empty
- `azure/` → `azure_api_key` AND `azure_api_base` must be non-empty

If any check fails, Sentinel refuses to start and prints a clear error like:
`SENTINEL_ANALYSIS_MODEL='anthropic/claude-sonnet-4-6' requires ANTHROPIC_API_KEY to be set`

This catches misconfiguration at startup, not mid-incident.

**Step 4 — .env.example rewrite.**
The example file was reorganized into provider-labeled sections and all new variables
were documented with comments explaining when they're needed and example values.

### Key Decision: Bare Model Names Still Work

Model strings without a `/` separator (e.g. `"llama-3.1-8b-instant"`) are allowed
through the validator without any key check. This is intentional backwards compat —
existing tests and scripts that don't yet use the `provider/model` format won't break.
Those bare names will be handled by the provider layer in task 9.3 (likely defaulting
to Groq via the `groq_base_url`).
