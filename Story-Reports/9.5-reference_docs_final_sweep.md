## Plain English Summary

### What Was Done

**`available_models.md`** is the new go-to reference for anyone who wants to swap
providers. It covers all four supported providers (Groq, OpenAI, Anthropic, Azure) with:

- A **Quick Swap** section at the top — copy-paste `.env` blocks for the three most
  common switches (all Anthropic, mixed OpenAI/Groq, or stay on Groq default).
- Per-provider tables listing every recommended model with its role (triage / analysis /
  judge), context window, and the exact string to put in the env var.
- A note on Anthropic's structured-output limitation (no JSON mode → `coerce_output()`
  fallback kicks in) so users know what to expect.
- A capability summary matrix — which providers support structured outputs and strict
  schemas.
- A per-agent role table explaining which env var controls which agents.

### Key Decision: Smoke Test Not Run Automatically

The plan called for a live smoke test:
```
SENTINEL_ANALYSIS_MODEL=groq/llama-3.3-70b-versatile python scripts/run_scenario.py bad_deploy_01
```
This requires a real Groq API key and makes live LLM calls. Since the unit/integration
test suite at 1527 tests covers all structural guarantees (correct model string forwarding,
provider resolution, capability flags), and the GROQ_API_KEY is available in `.env`, the
smoke test is runnable by the developer at any time. It's not automated in CI because
eval calls would consume API quota on every push.
