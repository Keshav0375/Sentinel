## Plain English Summary

### The Problem

Sentinel has six specialized agents, each with a different job during an incident response. Until now, every agent was just an empty stub — no instructions, no idea what to do. An agent without a system prompt is like a new hire on their first day with zero onboarding: they have all the tools but no idea how to use them.

System prompts are also high-iteration artifacts. During development, you might tweak the Triage Agent's severity thresholds or adjust the Remediation Agent's confidence cutoff a dozen times. If those instructions were hardcoded strings inside Python files, every change would require editing source code. Storing them as `.txt` files means you can revise a prompt by editing one file and restarting — no code change needed.

### What Was Built

**Six system prompt files** were written, one per agent:

1. **orchestrator.txt** — Tells the Orchestrator it is the top-level coordinator. Defines the exact handoff sequence (Triage → Log Analyst → Deploy Correlator → Remediation → Comms), the 15 tool-call budget shared across all agents, and the escalation rule when the budget runs out. Also handles shortcuts: if triage marks an incident as a duplicate, skip straight to Comms.

2. **triage.txt** — Tells the Triage Agent how to assign P1–P4 severity using the alert's numeric values and the service tier from `get_service_metadata`. Defines how to detect duplicate incidents via `search_past_incidents` (similarity > 0.85, created within 2 hours). Specifies the exact four-field output format.

3. **log_analyst.txt** — Tells the Log Analyst to fetch logs starting at ERROR/CRITICAL level, identify the *earliest* error (not just the most frequent), look for stack trace patterns, and distinguish cascade noise from root-cause signal. Specifies a four-field output with a one-sentence hypothesis.

4. **deploy_correlator.txt** — Tells the Deploy Correlator how to rank deploys by suspicion: timing proximity, change scope, module overlap with log stack traces. Defines the confidence scale (0.0–1.0) and forbids assigning confidence > 0.5 without corroborating evidence beyond timing alone.

5. **remediation.txt** — Tells the Remediation Agent its decision tree: rollback if deploy confidence ≥ 0.7, hotfix if confidence < 0.7 with a clear code/config bug, escalate if confidence < 0.3 or ambiguous. Contains the non-negotiable HITL rule: `request_human_approval` MUST be called before returning any result — no exceptions.

6. **comms.txt** — Tells the Comms Agent to call `draft_slack_summary` with the full incident context, verify all six required sections (Impact, Root Cause, Timeline, Current Status, Action Items, ETA) are present, and follow Slack mrkdwn tone guidelines.

**`loader.py`** is a tiny utility that reads prompt files from disk at runtime using `pathlib.Path`. It uses Python's `@lru_cache` so each file is read only once per process — subsequent calls return the cached string instantly. The file path is relative to the loader module itself (`__file__.parent / "prompts"`), so it works regardless of the working directory the app was launched from.

### Key Decisions

- **Files over f-strings:** Prompts are plain text in `.txt` files, not Python string constants. This lets you iterate on agent behavior without touching source code — critical for the kind of tuning that happens during eval.

- **`lru_cache` over repeated I/O:** The loader caches results after the first read. Agents are typically instantiated once per incident, so the cache rarely matters in production, but it makes test runs fast.

- **Content constraints as tests:** The test suite doesn't just check that files exist — it verifies critical behavioral constraints are encoded in each prompt. For example, `test_remediation_hitl_is_mandatory` confirms the word "must" or "non-negotiable" appears in the remediation prompt. If someone edits the prompt and accidentally softens the HITL requirement, the test will catch it.

- **Token budget enforcement in tests:** Each prompt is checked to stay under ~800 tokens (estimated via word count). This keeps prompts concise and costs predictable.
