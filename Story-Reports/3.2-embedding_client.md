## Plain English Summary

### What problem this solves

The episodic memory subsystem stores past incidents as vectors, and when a new incident arrives it searches for similar past cases by comparing vectors. To do any of this, Sentinel needs to convert text (symptom descriptions) into floating-point vectors. The `EmbeddingClient` is that conversion utility — it wraps a sentence-transformers model, offloads the CPU-intensive inference to a background thread so it doesn't block the async event loop, and caches results so the same symptom string is never embedded twice.

### What was built

**`EmbeddingClient`** is a lightweight wrapper class that takes any object with an `encode(texts, ...)` method and turns it into an async embedding service.

**`embed(text) -> list[float]`** embeds a single string. Internally it calls `embed_batch([text])` and returns the first element. Every embedding result is cached by the text string as the key. Calling `embed("same text")` a hundred times triggers only one model inference call; the rest are O(1) dict lookups.

**`embed_batch(texts) -> list[list[float]]`** embeds a list of strings. Before calling the model, it checks the cache and builds a deduplicated list of only the strings not yet seen. This deduplication works within a single call (if `["a", "a", "b"]` is passed, the model only sees `["a", "b"]`) and across calls (if `"a"` was embedded in a previous call, it's already in the cache). The model inference runs in a thread pool via `asyncio.to_thread()` to keep the event loop free during the CPU-bound work. Results are assembled in the original input order from the cache.

**`from_model_name(model_name)`** is a class factory that loads a real `SentenceTransformer` model by name. The import of sentence-transformers (which pulls in torch, transformers, etc.) is deferred inside this method — not at module level. This means importing `EmbeddingClient` in tests is fast, and only code that actually calls `from_model_name()` pays the torch import cost.

**`cache_size`** and **`clear_cache()`** give callers visibility into and control over the cache. In practice, the cache is cleared when the `EmbeddingClient` object is garbage-collected (per incident). For long-running processes, `clear_cache()` can be called explicitly.

### Key decisions and trade-offs

**Model injected via constructor, not instantiated internally** — `EmbeddingClient(model)` takes the model as a dependency rather than calling `SentenceTransformer(model_name)` in `__init__`. This follows the CLAUDE.md dependency injection pattern and is what makes the tests fast: they inject a `_FakeModel` that returns deterministic numpy arrays without loading torch. The `from_model_name()` factory exists for convenience in application startup code.

**Lazy import of sentence-transformers** — `SentenceTransformer` is imported inside `from_model_name()`, not at module level. This keeps the module import cost near-zero and avoids triggering torch initialization during test collection. The 20 tests run in ~2 seconds with the fake model versus ~10+ seconds if the real model loaded.

**`asyncio.to_thread` with a lambda** — `model.encode()` is synchronous (runs torch inference on CPU or GPU). Running it directly in an async function would block the event loop during inference. `asyncio.to_thread(lambda: model.encode(...))` offloads it to the thread pool. Using a lambda rather than passing args positionally to `to_thread` makes the keyword arguments to `encode()` explicit and readable.

**Cache stores `list[float]`, not `np.ndarray`** — The cache value type is `list[float]` (Python native) rather than numpy arrays. This avoids numpy as a transitive dependency of the cache, and `EpisodicRecord.embedding` is already `list[float]`. The conversion from numpy row to `list[float]` happens once at cache-write time via `.tolist()` — subsequent reads return clean Python types.
